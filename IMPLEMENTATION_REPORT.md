## 4. What "everything in the MDs" resolves to

`IMPLEMENTATION_LEDGER.md` (generated by `tools/build_ledger.py`, cross-checked by
the audit) classifies all 105 named rows of the target map:

- **98 IMPLEMENTED** — a real, wired back end that compiles and emits the right
  container: 9 native ISAs (x86-64, aarch64, armv7, riscv64, ppc64le, s390x,
  mips64/el, loongarch64); 3 containers (ELF, PE32+, Mach-O) plus fat Mach-O, SXE

  Windows exe/dll/arm64; Android; the full WASM family (11 variants); GPU (PTX,

  C#, CIL, CIL-PE, JS, TS); firmware (bare x86-64/Cortex-M/RV32/RV64, ihex, srec,
  uf2, dfu, mcuboot); UEFI x86-64/arm64; the C and LLVM-IR reach-multipliers;
  **plus the fifty-nine added across these rounds — eBPF, QBE IR, Multiboot1, DOS `.COM`,
  DOS MZ `.EXE`, COFF `.obj`, macOS `arm64e`, macOS `arm64_32`, Linux `i386`, `x32`,
  `riscv32`, `mipsel`, big-endian `mips`, `ppc64`, `ppc32`, `armhf`, `thumbv7a`,
  `sparc64`, `m68k`, `microblaze`, `openrisc`, `nios2`, `sh4`, `sparc_v8`, and the
  `x86-64-v2`/`-v3`/`-v4` micro-architecture levels, the `armv5` OABI target
  (`armel` old-ABI, `swi #0x9000nn`), and the RISC-V extension-flag family —
  `riscv64+V`, `riscv64+H`, `riscv32+Zfinx`, `riscv32+Zdinx` — each carrying a
  real `.riscv.attributes` section (SHT 0x70000003, `Tag_RISCV_arch` ULEB128), and the
  `armv7a-armel` EABI5 soft-float target (r7 + `svc #0`, `.ARM.attributes`), the `.a`
  static archive (ar(1) around an ELF relocatable object, `ar t`-clean), the
  `hypervisor` privileged ELF64 (PT_NOTE entry ABI), `.eh_frame` (DWARF CIE+FDE that
  `readelf --debug-dump=frames` decodes), `.pdata` (PE RUNTIME_FUNCTION), and the
  `windows-store` / `windows-arm64ec` PE variants, the HarmonyOS/OpenHarmony HAP
  (a CRC32-checked ZIP with a valid `module.json`), and four new ISA code
  generators — AVR (EM 83), MSP430 (EM 105), ARC (EM 93, `trap0` ABI) and Xtensa
  (EM 94, a2/a6/a3/a4/a5/a8/a9 ABI), and the Dalvik `.dex` container whose
  Adler-32 and SHA-1 signatures are both computed by the compiler itself
  (SHA-1 written in sovren, byte-verified against Python's `hashlib`), the AIX
  XCOFF64 container (magic `0x01F7`, `o_mflag` `0x010B`, `F_EXEC`), and the Plan 9
  a.out container (amd64 `S_MAGIC` `0x8A97` with the 8-byte `HDR_MAGIC` header
  expansion), and the Fuchsia FAR package container (index / DIR----- / DIRNAMES /
  4096-aligned content chunks), the Qualcomm Hexagon ELF32 backend, big-endian
  `riscv64-be`, the three AArch64 extension variants (SVE/SVE2/MTE, each carrying a
  real `.ARM.attributes` and a `.note.gnu.property` whose BTI/PAC/GCS bits

- **1 DEFERRED** (2 ledger groups) — `pic24`/`dspic33` (no ELF `e_machine` exists

Every deferred/blocked item carries the spec's own reason; none is a gap in the
buildable first list — that list is **fully implemented and green**.

## 5. New backends implemented this round

Thirty-four targets that the MDs name but the tree did not yet have were implemented
from scratch, each through the documented "five places" (kit source + binary,
`launcher.sov` route + help, `bootstrap.sov` `bo_step`, a `tests/run.sov`
`ck_` check, and the committed launcher binaries `sovren`/`sovren.exe`), and each
verified byte-reproducible by a clean bootstrap:

| flag | kit | MD ref | what it emits |
|---|---|---|---|

Every one is a real backend: it parses the deterministic command-subset `main`,
lowers the result, and emits the target's container with the correct machine /
ABI fields and instruction sequence (verified byte-for-byte, and the `--i386`
image actually executes and exits with the result). Bootstrap rebuilds every kit
byte-for-byte from source, the suite is at 225 passing checks (0 failed), and the
audit verifies 251 flags.
