Working out what went wrong on Windows
======================================

When a Sovren program on Windows does nothing at all, run it like
this so you can see the exit code:

    .\thing.exe; echo "exit=$LASTEXITCODE"

The number tells you what happened. These are the ones that matter.


exit=0
    It ran and finished normally.

exit=1
    The compiler found a mistake in your program and said so.

exit=-1073741795   (0xC000001D  STATUS_ILLEGAL_INSTRUCTION)
    The processor met an instruction it does not have. This is what
    happened with AVX-512: the machine that built the compiler had
    it, yours did not. Nothing prints because the program is killed
    before its first write.
    Check with:  sh check/run     (looks for AVX-512 in the output)

exit=-1073741819   (0xC0000005  ACCESS_VIOLATION)
    Read or write to memory that is not there. Usually a null
    pointer, or a section marked read only that is written to.

exit=-1073741515   (0xC0000135  DLL NOT FOUND)
    Windows could not load something the program imports. For
    Sovren that means the import table is wrong, since the only
    library used is KERNEL32.dll.

exit=-1073740791   (0xC0000409  STACK BUFFER OVERRUN)
    The stack was corrupted. Often a calling convention mistake:
    Windows wants 32 bytes of shadow space and 16 byte alignment
    before every call.

exit=-1073741511   (0xC0000139  ENTRYPOINT_NOT_FOUND)
    Windows could not resolve a function in the import table. The
    usual cause is a malformed table: the IAT and the ILT must hold
    the same values, must each end with a zero, and the two must not
    overlap. Adding imports without moving the ILT does exactly this.
    Check with:  sh check/run     (windows-import-table)

exit=-1073741510   (0xC000013A)
    You pressed ctrl-C.


Nothing prints and the exit code is 0
    The program ran but wrote nothing. Check that stdout is really
    a console: piping into another program changes the handle.


A file is written but is not a valid program
    Check the header:

        python3 windows/run_pe.py yourfile.exe

    That is a strict emulator. Unlike Wine it refuses raw Linux
    syscalls, so it catches the mistake Wine hides.


Keys do nothing in a full screen program
    The console is in line mode: it holds your typing until you
    press enter, and eats ctrl-key combinations. Sovren asks for
    raw mode through the terminal ioctls, which the compiler turns
    into GetConsoleMode and SetConsoleMode. If that is not working
    the editor will look frozen and ctrl-S will not save.


Why Wine is not enough
----------------------
Wine runs on Linux. A raw `syscall` instruction inside a Windows
program falls straight through to the Linux kernel and appears to
work. On a real Windows machine there is no Linux kernel underneath
and the program dies quietly. Two separate bugs hid behind this.

Anything the compiler emits for Windows must therefore:
  - use kernel32, never a raw syscall
  - avoid instructions the target CPU may not have
  - not claim ASLR, because the image has no relocation table

`sh check/run` tests all three.
